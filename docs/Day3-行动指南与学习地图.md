# Day3-行动指南与学习地图

## 1. Day3 今天的主线是什么

Day3 不会一上来就猛写菜品接口。

今天的正确节奏是先做一件很像“工程升级”的事情：

- 先把公共字段自动填充做出来
- 再进入菜品管理

这里的“公共字段”指的是这些经常重复出现的字段：

- `createTime`
- `updateTime`
- `createUser`
- `updateUser`

你可以先把它理解成：

- 以前我们在员工、分类这些业务里，每次新增、修改都要手动补这些值
- 这样代码很重复，也很容易漏
- Day3 要先把这类重复劳动抽走，交给程序自动完成

这一步做完后，后面写菜品、套餐、订单时都会更顺手。

## 2. 为什么 Day3 要先做这一步

因为从 Day2 开始，你已经接触到了很多标准 CRUD。

这时如果继续无脑往后堆接口，会出现两个问题：

- 同样的字段赋值代码到处复制
- 以后模块一多，维护会越来越乱

所以 Day3 的第一步不是“多做一个功能”，而是：

- 先把项目整理得更像企业写法

你要记住一句最重要的话：

- Day2 练的是“把功能做出来”
- Day3 先练的是“把重复代码收起来”

## 3. 今天我们要完成的 3 件事

### 第一件事：验证公共字段自动填充

目标：

- 确认即使 Service 不再手动写时间和操作人
- 数据库里这些字段仍然能正确入库

你要验证的场景：

- 新增员工
- 修改员工
- 新增分类
- 修改分类

你要重点观察的不是页面漂不漂亮，而是：

- 数据有没有成功改进数据库
- `createTime` / `updateTime` 有没有自动变化
- `createUser` / `updateUser` 有没有自动写入

### 第二件事：把这套机制真正理解掉

今天你至少要明白下面 4 个角色分别在干什么：

- `@AutoFill`：打标记，告诉程序“这个方法需要自动填充”
- `OperationType`：告诉程序这是新增还是修改
- `AutoFillAspect`：真正出手帮我们自动赋值的切面
- `BaseContext`：拿到当前登录人的 id

### 第三件事：准备进入菜品管理

公共字段自动填充验证通过后，Day3 后半段才正式进入菜品管理，主线通常是：

- 新增菜品
- 菜品分页查询
- 删除菜品
- 修改菜品

## 4. 你今天最应该建立的理解

今天不是背代码，而是要建立一种“看项目”的眼光。

你要慢慢意识到：

- 很多业务代码其实是在做重复劳动
- 重复劳动就应该想办法抽出去
- AOP 不是为了炫技，而是为了统一处理横着分散在多个模块里的重复逻辑

这里的“横着分散”你可以先理解成：

- 员工有这几个公共字段
- 分类也有这几个公共字段
- 菜品以后大概率也有
- 那就不该每个模块都手写一遍

## 5. 你现在具体要怎么做

按这个顺序来就行：

1. 重启后端项目
2. 登录管理端，拿到最新 token
3. 用 APIFox 或前端页面分别测试新增和修改员工
4. 再测试新增和修改分类
5. 去 Navicat 看数据库字段是否自动填充成功

## 6. 你测试时只盯住这 5 个观察点

不要一下看太多，只盯这 5 件事：

1. 请求是否返回成功
2. 控制台是否打印了“开始进行公共字段自动填充...”
3. 新增时 `createTime` 和 `updateTime` 是否都写入
4. 修改时 `updateTime` 是否更新
5. `createUser` / `updateUser` 是否来自当前登录人

## 7. 如果测试失败，优先怎么查

按这个顺序查最稳：

1. 先确认请求是否真的打到了后端
2. 再确认对应的 Mapper 方法上有没有 `@AutoFill`
3. 再确认切面是否被 Spring 扫描到
4. 再确认当前请求线程里有没有拿到 `BaseContext` 里的用户 id
5. 最后再看实体类里是否真的存在对应的 setter 方法

## 8. 今天你要先记住的几句话

- 注解像“标签”，先标记目标
- 切面像“代办员”，在真正执行数据库方法前先帮你补字段
- `BaseContext` 像“当前登录人小纸条”，当前线程里随时可拿
- 反射像“动态调用工具”，程序运行时按方法名去调用 setter

## 9. Day3 今天的学习价值

如果 Day2 更像“学会做表单 CRUD”，那 Day3 前半段更像：

- 第一次真正接触一点工程化思维

这一步的价值不是只为了当前员工和分类，而是为了后面很多模块都能少写重复代码。

所以今天真正的收获应该是：

- 你开始知道，后端不只是堆接口
- 还要不断把重复逻辑抽象出来
- 让代码更整洁、更稳、更容易扩展

## 10. 今天完成后的交付标准

今天这一小阶段完成，至少要满足这几个标准：

- 你能说清公共字段自动填充解决了什么问题
- 你能说清为什么注解打在 Mapper 方法上
- 你能说清切面是在什么时候执行的
- 你能亲自验证数据库字段确实自动填充成功
- 你准备好进入 Day3 的菜品管理主线
