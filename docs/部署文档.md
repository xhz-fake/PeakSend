# 部署文档

## 1. 文档目标

这份文档的目标不是讲某一天做了什么，而是告诉别人：

- 这个项目是什么
- 本地需要准备什么
- 每个配置落在哪
- 如何把项目在自己的机器上真正跑起来
- 跑起来之后怎么验证关键链路

当前文档面向的是：

- 本地开发复现
- 面试展示
- 项目交付说明

不是生产环境部署手册。

---

## 2. 项目概览

PeakSend（峰送商配平台）是一个围绕本地生活配送场景构建的全栈商配平台项目，覆盖：

- 管理端：商品、分类、套餐、订单处理、工作台、统计报表
- 用户端：商品浏览、购物车、下单、历史订单、地址簿
- 工程能力：Docker、Redis、RocketMQ、Nacos、Gateway、OpenFeign、`traceId` 全链路追踪

当前本地运行形态为：

- `nginx -> gateway -> sky-server -> product-service`

其中：

- Nginx 负责统一外部入口
- Gateway 负责网关路由
- `sky-server` 承担主业务服务
- `product-service` 承担商品查询服务

- Docker Desktop（或其他可用 Docker 环境）

1. 用 `docker compose` 拉起基础环境与容器化服务
2. 通过浏览器 / 小程序入口验证核心链路

## 7. 关键配置文件说明

### 7.1 Docker 编排总入口

- [docker-compose.yml](../docker-compose.yml)

这里决定：

- 起哪些容器
- 容器之间怎么通信
- 哪些环境变量会喂给各个服务

如果你要改：

- MySQL 密码
- Redis 密码
- Nacos 地址
- RocketMQ 地址
- 是否开启 MQ 相关能力

优先看这里。

### 7.2 Nginx 路由配置

- [docker/nginx/nginx.conf](../docker/nginx/nginx.conf)

当前路由规则是：

- `/api/**` -> `gateway:8082`
- `/user/**` -> `gateway:8082`
- `/ws/**` -> `gateway:8082`

这意味着当前外部访问统一建议走：

- `http://localhost:8081`

### 7.3 `sky-server` Docker 运行配置

- [application-docker.yml](../peaksend-backend/sky-server/src/main/resources/application-docker.yml)

这里主要负责：

- MySQL 连接
- Redis 连接
- Nacos 注册发现
- RocketMQ 开关与延迟级别
- 上传目录
- 微信支付模式

### 7.4 Gateway 配置

- [sky-gateway/application.yml](../peaksend-backend/sky-gateway/src/main/resources/application.yml)

这里主要负责：

- 按服务名路由到 `sky-server`
- 管理端、用户端、WebSocket 三类入口分流

### 7.5 `product-service` 配置

- [product-service/application.yml](../peaksend-backend/product-service/src/main/resources/application.yml)

这里主要负责：

- 商品服务端口
- 数据库连接
- Nacos 注册发现
- 日志 `traceId` 格式

### 7.6 小程序本地入口

- [miniProgram/utils/env.js](../miniProgram/project-rjwm-weixin-uniapp-develop-wsy/utils/env.js)

当前本地配置已经统一为：

- `http://localhost:8081`

这一步很重要，因为如果仍然直连 `8080`，就会绕过 gateway，导致：

- 微服务链路验证失真
- `traceId` 网关入口逻辑无法经过

## 10. 关键链路验证建议

### 10.1 管理端验证

推荐动作：

- 打开管理端首页
- 登录后点击“菜品管理”

预期：

- 请求从 `8081` 进入
- 经过 `nginx -> gateway -> sky-server`
- Network 响应头中可看到 `X-Trace-Id`

### 10.2 用户端/小程序验证

推荐动作：

- 打开小程序首页
- 进入点餐页
- 加购一个商品

预期：

- 请求经过 `nginx -> gateway -> sky-server`
- 查询商品信息时继续进入 `product-service`
- Day19 的 `traceId` 可以串起整条链路

## 11. 常见修改项怎么配

### 11.1 修改 MySQL 密码

需要同步改的地方：

1. `docker-compose.yml` 中 `mysql` 的 `MYSQL_ROOT_PASSWORD`
2. `docker-compose.yml` 中 `backend` / `product-service` 的 `DB_PASSWORD`

### 11.2 修改 Redis 密码

需要同步改的地方：

1. `docker-compose.yml` 中 `redis` 的 `--requirepass`
2. `docker-compose.yml` 中 `backend` 的 `REDIS_PASSWORD`

### 11.3 调整 RocketMQ 能力开关

当前由 `docker-compose.yml` 中 `backend` 环境变量控制：

- `SKY_ROCKETMQ_ENABLED`
- `SKY_ROCKETMQ_ORDER_DELAY_ENABLED`
- `SKY_ROCKETMQ_FLASH_SALE_ASYNC_ENABLED`
- `SKY_ROCKETMQ_ORDER_DELAY_LEVEL`

### 11.4 调整小程序本地入口

修改：

- `miniProgram/project-rjwm-weixin-uniapp-develop-wsy/utils/env.js`

本地建议保持：

- `http://localhost:8081`

不要改回 `8080`。

## 12. 常见问题排查

### 12.1 `docker compose up -d` 报找不到配置文件

原因通常是：

- 当前终端不在项目根目录

正确方式：

```powershell
cd /d D:\ProgramFiles\CodeProjects\PeakSend
docker compose up -d
```

### 12.2 管理端能打开但接口 502 / 404

优先排查：

1. `docker compose ps`
2. `docker compose logs gateway`
3. `docker compose logs backend`
4. Nacos 是否健康、服务是否注册

### 12.3 小程序能请求但 Day19 链路不完整

优先排查：

1. `env.js` 是否仍走 `8081`
2. gateway 是否正常
3. backend / product-service 日志里是否出现同一个 `traceId`

### 12.4 `product-service` 没有被调用

不要立刻判断成 Feign 失效，先确认：

- 当前业务是否真的命中了跨服务分支

例如购物车加购，如果商品已存在，可能直接走本地更新，不一定再次查商品服务。

## 13. 停止与清理

### 13.1 停止容器

```powershell
docker compose stop
```

### 13.2 停止并移除容器

```powershell
docker compose down
```

### 13.3 停止并移除容器、网络、匿名卷

```powershell
docker compose down -v
```

注意：

- `-v` 会影响 MySQL / Redis 数据卷，谨慎使用
